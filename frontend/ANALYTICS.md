# Website measurement

GA4 web stream: `G-Y3WJ7KXW9V`, supplied by the user on 3 November 2026.

The Google tag is appended to the document head once after an explicit analytics acceptance. There is no Google script request before acceptance or after a stored rejection. Basic consent defaults deny analytics and all advertising purposes; acceptance grants only analytics storage. Google signals and personalised advertising remain disabled. Choices last up to 180 days and can be changed from Cookie settings in the marketing footer or the privacy page. After acceptance or rejection, the banner closes and no floating settings button remains. Reopening the controls and closing them returns keyboard focus to the original footer or privacy-page button. Rejection disables further collection and clears accessible `_ga` cookies. A storage failure preserves the choice for the current visit.

Only production builds on `greenturtletraders.co.uk` and its `www` hostname can load the tag. Local previews and development builds never send Analytics data. General measurement is limited to configured indexable public routes, excluding Contact and Turtle Analytics (which share form/account functionality). Application and enquiry input screens, admin, unknown paths, URLs with query strings and authenticated/modal screens are excluded. A guard runs before Google’s history listeners; excluded routes are disabled before the History API changes the URL. No application fields, uploaded documents, user identifiers or account information are passed to Analytics by this integration. The initial referrer is reduced to its origin.

After a real server response confirms `ok: true` and supplies a submission ID, the form is replaced by a generic confirmation screen. That screen can send `investor_enquiry_submitted` or `trader_application_submitted`, with the fixed `lead_type`, page location/title and measurement destination. No form fields are permitted to remain mounted when measurement is enabled. Submission IDs deduplicate repeated confirmation effects in memory only; they are never sent to Google. Demo submissions, failed or malformed responses and validation failures generate no completion event. Rejected or unknown analytics consent also generates no completion event. Navigation away clears the confirmation exception, so returning to an unfinished form disables measurement again.

## Google Analytics settings

Keep Enhanced measurement page views and **Page changes based on browser history events** enabled in this web stream. Google handles route page views; the site does not send additional manual page views. Do not install a second tag through Tag Manager or another integration. For a minimal measurement setup, disable automatic form interactions and site search in the stream. The two explicit completion events above provide the lead counts.

After deployment, accept analytics in a fresh browser session and check the homepage, investor and trader journeys in GA4 Realtime or DebugView. A visitor who rejects analytics is intentionally absent from these reports. Installation detection tools may not see the Google tag until analytics is accepted.

In GA4 **Admin → Data display → Events**, mark `investor_enquiry_submitted` and `trader_application_submitted` as key events. They can be registered before they first appear: **Create event**, enter the exact name, mark as a key event, and select creation with code if prompted (the website already emits the event). Use **Once per event** and no default monetary value. No URL-based or click-based derived event is needed. This account-side configuration requires access to the GA4 property and does not apply retroactively. Compare these consented event counts with organic-search landing sessions; they are not a complete count of all submissions held by the application database.

## Verification

`npm run check:analytics` exercises the actual TypeScript guard, including consent order, one script, public and private routes, sensitive query strings, withdrawal, cookie clearing, persistence, blocked storage, cross-tab changes and completion-event deduplication/parameter exclusions. Run `npm run build` and `npm run check:seo` alongside it. Browser checks cover form validation, failed and malformed server responses, confirmed submissions, consent refusal, refresh and the absence of personal data in collection requests. All application endpoints and Google collection requests must be intercepted during these checks, so no test applications, emails or production Analytics lead events are created.
